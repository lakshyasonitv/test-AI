## 2. HOW TO TRY IT

`RUN_QUESTIONS=true`, restart the server (`npm run serve` does not reload), start a run against
the org's login URL with credentials. If the org shows "Verify your identity", a "Verification
code needed" box appears; type the code from the email/SMS/app. Skip or wait out
`QUESTION_WAIT_MS` and the run continues unauthenticated, as before.

## 3. DELIBERATELY NOT DONE

- Saved-case replays and suites get no session (TD-115).
- Salesforce's "a verified browser is not asked again" is assumed from the fixture and the
  documentation, not seen against a live org — the build container cannot reach Salesforce.
- No question kinds beyond `verification-code`. The waiter, route and modal take a `kind`, so the
  next one is an addition, not a change.
- Rollback: set `RUN_QUESTIONS=false` (or unset it). Nothing is persisted, so there is nothing to
  clean up.
