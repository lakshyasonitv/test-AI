case A and passed on the second run of the same commit. A flake is not a root cause, so it was traced instead:
`playwright.config.ts` had `testDir: "./runs"`, so every spec start first scanned EVERY run folder under `runs/`, and a
folder another process deleted mid-scan ended the spec with `ENOENT ... scandir` before its first step. Tests clean up
their own `runs/0000-*` folders while other test files start specs, which explains CI; in production, a run folder
cleaned up while another run starts does the same, and D-73's parallel cases start more specs at once.
Fix (TD-185): `executor.ts` passes `PLAYWRIGHT_TEST_DIR` (the spec's own folder) to the Playwright child, and the
config reads `testDir: process.env.PLAYWRIGHT_TEST_DIR || "./runs"`. Unset means old behaviour; no route, flag or
generated-spec change. Proof: new `tests/specScanRace.test.ts` (three real `runSpec` calls while sibling folders under
`runs/` are created and deleted) failed 2 of 3 without the fix and passed 9 of 9 with it.
#19 merged (`aafa6f4`) after its rerun was green; the fix went in as PR #20 (merged `10381ba`).
